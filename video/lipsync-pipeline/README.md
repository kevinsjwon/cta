# 립싱크 영상 파이프라인 (lipsync-pipeline)

캐릭터 이미지와 대본을 넣으면, 두 캐릭터가 대화하며 입 모양이 맞춰진(립싱크)
유튜브용 영상을 자동으로 만드는 도구 모음입니다.

이 문서는 **AI나 프로그래밍을 잘 모르는 분도 전체 그림을 이해할 수 있도록** 쉬운 말로
정리한 안내서입니다. 실제 세부 규칙과 수치, 그동안 겪은 시행착오는 같은 폴더의
[`PROCESS.md`](PROCESS.md)에 매우 자세히 적혀 있습니다. (이 README를 먼저 읽고,
직접 만들 때 `PROCESS.md`를 참고하는 순서를 권합니다.)

---

## 1. 무엇을 만드는 도구인가

- **입력**: 캐릭터 이미지 몇 장 + 대본(표 형태의 워드 문서)
- **출력**: 두 캐릭터가 번갈아 말하는 40~50초 세로 영상(유튜브 쇼츠용 1080×1920)
  또는 가로 영상(1920×1080)

즉, "대사만 써 주면 캐릭터가 그 대사를 말하는 영상"을 만들어 줍니다.
사람이 매번 입 모양을 그리거나 편집하지 않아도 됩니다.

### 용어 간단 설명
- **립싱크**: 소리(대사)에 맞춰 캐릭터의 입 모양을 움직이는 것.
- **TTS(음성 합성)**: 글로 쓴 대사를 컴퓨터가 목소리로 읽어 주는 기능.
- **프레임**: 영상을 이루는 한 장 한 장의 그림. 이 도구는 1초를 24장으로 만듭니다.

## 3. 실행에 필요한 환경

- **Node.js 18 버전 이상** (제작 검증 버전: v24.18.0)
- **운영체제: macOS / Windows / Linux 모두 지원.** 코드가 `process.platform`을 감지해
  OS에 맞는 한국어 TTS 엔진과 자막 폰트를 자동으로 고릅니다. OS별 준비물은 아래와 같습니다.

| OS | 한국어 TTS | 자막 폰트 | 준비 방법 |
| --- | --- | --- | --- |
| **macOS** | 내장 `say` (음성 Yuna) | Apple SD Gothic Neo (내장) | 시스템 설정 → 손쉬운 사용 → 음성 콘텐츠에서 Yuna 내려받기 |
| **Windows** | 내장 SAPI (음성 예: Microsoft Heami) | Malgun Gothic (내장) | 설정 → 시간 및 언어 → 음성에서 한국어 음성 추가 |
| **Linux/클라우드** | `espeak-ng` (또는 `piper`+한국어 `.onnx` 모델) | Noto Sans CJK KR | `sudo apt-get install -y espeak-ng fonts-noto-cjk` |

- TTS 엔진은 `speakers.tsv`의 `rate`(macOS `say` wpm 기준)를 엔진별 속도로 **근사 매핑**합니다
  (espeak `-s` ≈ wpm×1.1, SAPI Rate ≈ (wpm−200)/25, piper `length_scale` ≈ 200/wpm).
  엔진마다 목소리 음질과 정확한 발화 길이는 다르지만 **시각 파이프라인(입모양·표정·합성·자막)은
  완전히 동일**합니다. 총길이가 목표 범위(§`PROCESS.md` 6)를 벗어나면 01단계가 보정 지시를 냅니다.
- 환경변수로 강제 지정도 가능합니다: `TTS_ENGINE=say|sapi|espeak|piper`, `CAPTION_FONT="..."`,
  `SAPI_VOICE="..."`, `PIPER_MODEL=/path/to/model.onnx`, `FONTS_DIR=/path`.

설치는 이 폴더에서 아래 한 줄이면 됩니다. (부품을 내려받는 과정입니다.)
```bash
npm install
```

## 4. 전체 흐름 (쉬운 말로)

캐릭터 이미지와 대본이 준비된 상태에서, 크게 아래 순서로 진행됩니다.
(명령어와 정확한 순서는 `PROCESS.md`의 "11. 실행 순서"에 있습니다.)

1. **대본 읽어 들이기** — 워드 대본을 프로그램이 쓰는 형식으로 바꿉니다.
2. **목소리 만들기** — 대사를 한국어 음성으로 합성하고, 두 캐릭터의 목소리를 다르게 합니다.
3. **입 모양 계산** — 한글은 글자만 봐도 입 모양을 정확히 알 수 있어서, 소리 인식 없이
   글자에서 입 모양(9종)을 뽑아냅니다. 그래서 결과가 항상 똑같이 재현됩니다.
4. **자막 만들기**
5. **캐릭터 화면 배치** — 말하는 사람은 정면(입이 움직임), 듣는 사람은 앞쪽에 뒷모습으로
   크게 배치하는 "대화 영상 문법"을 자동으로 적용합니다.
6. **영상으로 내보내기** — 배경·캐릭터·자막을 합쳐 최종 영상 파일을 만듭니다.
7. **검증** — 입/표정이 바뀔 때 캐릭터가 흔들리지 않는지 자동으로 확인합니다.

핵심 설계 원칙은 **"결과가 매번 똑같이 나오게(재현 가능하게) 만든다"** 입니다.
그래서 입 모양은 AI로 생성하지 않고 글자에서 계산하며, 무작위 요소도 고정된 규칙을 씁니다.

## 5. 새 캐릭터로 "같은 구도"의 영상 만들기

이 도구의 목적 중 하나는, **다른 캐릭터 이미지를 받아도 이전과 같은 구도·연출의 영상을
만드는 것**입니다. 방법은 다음과 같습니다.

1. 새 캐릭터 이미지를 정해진 이름 규칙에 맞춰 `assets/` 아래에 넣습니다.
   ```
   assets/
     <캐릭터이름>/          ← 폴더 이름 = 대본에 나오는 화자 이름
       앞_기본.png          ← 필수: 무표정 앞모습
       앞_<표정>.png        ← 선택: 설명 / 경고 / 놀람 등 (개수·이름 자유)
       뒤.png               ← 필수: 뒤통수 (대화 장면에서 앞쪽에 놓임)
     scene.png              ← 선택: 배경·책상을 떠올 참고용 완성 장면
     대본.docx              ← 5열 표(번호 / 화자 / 대사 / 컷 / 화면)
   ```
2. `PROCESS.md`의 "11. 실행 순서"를 그대로 따라 실행합니다.
3. 화면 배치(캐릭터 크기·위치·구도)는 프로그램이 **이미지 픽셀을 측정해 자동으로**
   계산합니다. 그래서 캐릭터가 바뀌어도 같은 구도가 유지됩니다.
   사람이 직접 숫자를 넣는 경우는 원본 그림에 결함이 있을 때의 예외 처리뿐입니다.

즉, **"정해진 이름으로 이미지 넣기 + 대본 넣기 + 정해진 순서 실행"** 이 반복되는 작업의
전부입니다. 구도를 매번 새로 잡을 필요가 없습니다.

> 캐릭터 이미지 준비 시 권장 사항(정면, 입 닫힌 상태, 얼굴이 뚜렷할 것 등)은
> `PROCESS.md` §7 끝부분과 §11의 "입력 계약"에 정리되어 있습니다.

## 7. 참고: 두 가지 제작 방식

`PROCESS.md`에는 두 가지 길이 함께 적혀 있습니다.

- **현행 방식(권장)**: 입 모양을 글자에서 계산해 붙이는 방식. 비용이 들지 않고,
  결과가 항상 똑같이 재현됩니다. (§5, §8.6, §11)
- **생성형 립싱크(선택)**: 외부 AI 서비스로 입을 움직이는 방식. 비용이 들고 결과가
  매번 달라지며, 이 프로젝트처럼 평면 2D 동물 캐릭터에서는 대부분 실패합니다
  (Flyworks만 작동 확인). 필요할 때만 제한적으로 씁니다. (§9)

`PROCESS.md`에는 폐기된 방식(§7의 일부, §8.7, §9의 일부)도 **일부러 남겨** 두었습니다.
같은 실수를 반복하지 않기 위해서이며, "폐기됨(⛔)"으로 표시되어 있으니 그 부분은
따라 하지 마세요.
