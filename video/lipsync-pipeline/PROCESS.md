# 동물 캐릭터 대화 립싱크 영상 — 재현 가능 프로세스

임의의 **토픽 · 대본 · 캐릭터 이미지 · 배경**을 입력받아 40~50초(또는 임의 길이)
2인 대화 립싱크 영상을 자동 생성한다. 이 문서만으로 다른 컴퓨터에서 동일하게 동작한다.

- 입력이 바뀌어도 작동하는 **방식과 장치**를 규정한다. 특정 대본/캐릭터에 의존하지 않는다.
- 마지막 검증: 2026-09-04, macOS Darwin 25.6.0 (arm64), Node v24.18.0

---

## 이 문서를 처음 읽는다면 — 어디가 현행인가

이 저장소는 여러 경로를 시도하고 폐기한 기록을 **일부러** 남겨 두었다. 같은 실수를
반복하지 않기 위해서다. 그래서 **지금 쓰는 경로와 폐기된 경로가 한 문서에 같이 있다.**

| 구분 | 절 | 상태 |
|---|---|---|
| **현행 제작 경로** | **§11(실행) + §8.6(원리)** | ✅ 이것만 따라 하면 된다 |
| 공통 기반 (오디오·입모양·자막) | §3 ~ §6 | ✅ 현행 |
| 대본·플롯 구성 | §8 ~ §8.5 | ✅ 현행 |
| 합성 캐릭터를 그려서 렌더 (`03-render`) | §7 | ⛔ 다른 경로. 외부 아트를 받는 지금 방식엔 안 씀 |
| 컷아웃만 있을 때의 초기 시도 (`09-render-static`) | §8.7 | ⛔ **폐기.** 실패 기록으로만 읽을 것 |
| 생성형 립싱크 (Flyworks/Replicate) | §9 | ⛔ 평가 완료·불채택. 판단 근거로만 |

**요약**: 새 작업은 §11 실행 순서대로 돌리고, 막히면 §8.6 을 읽는다.
**입력은 "캐릭터 이미지 폴더 + 대본 docx" 둘뿐이다.** 배치·ROI·귀 복원값 같은 숫자는
`23-measure` 가 픽셀에서 뽑고 `25-make-layout` 이 배치를 만든다. 손으로 적는 값은
원본 아트에 결함이 있을 때의 `overrides` 뿐이다.
§7·§8.7·§9 의 지시를 그대로 실행하면 이미 사용자가 반려한 결과가 나온다.

## 0. 핵심 설계 판단

| 판단 | 이유 |
|---|---|
| 입 모양은 **텍스트에서 결정론적으로** 뽑는다 | 한국어는 음절 문자다. 음성 인식을 거치지 않으므로 오인식이 원리적으로 없다. 영어권 도구(Rhubarb 등)는 영어 음소 인식기라 한국어 정확도가 떨어진다 |
| 입 모양은 **AI로 생성하지 않는다** | 매번 미묘하게 달라져 프레임이 튄다. 9종을 벡터/파라메트릭으로 고정하면 드리프트가 0 |
| 입은 **12fps**로 갱신, 영상은 24fps | 카툰 입은 뚝뚝 끊기는 게 자연스럽고 계산이 절반 |
| 캐릭터는 **1회 제작 후 영구 재사용** | 컷마다 생성하는 방식은 얼굴이 흔들린다. 영상당 이미지 비용이 0에 수렴 |
| 생성형 립싱크는 **훅 구간에만** | $3/분 수준이고 **비결정론적**이라 재렌더 시 결과가 달라진다 → 다편 채널의 일관성이 깨진다 |
| 난수는 **시드 LCG**만 사용 | `Math.random()`/`Date.now()`는 컴퓨터마다 결과가 달라져 재현성이 깨진다 |

## 3. 입력 명세

### `input/script.tsv` — 대본
탭 구분. `번호 ⇥ 화자 ⇥ 다음줄까지_간격(초) ⇥ 대사`

```
01	M	0.70	나는 하루 종일 주변을 살펴. 근데 내가 뭘 놓치는지는 몰라.
07	M	1.35	너 지금 색 바꿨어?
```

- **화자 ID**는 `speakers.tsv`와 일치해야 한다 (불일치 시 즉시 에러).
- **간격(gap)이 페이싱의 주 조절 수단이다.** 극적 비트는 1.0~1.4초, 일반 전환은 0.4~0.7초.
- 마지막 줄의 gap은 0.

### `input/speakers.tsv` — 화자
`ID ⇥ 음성 ⇥ 속도(wpm) ⇥ 피치배율 ⇥ 라벨`

```
M	Yuna	200	1.00	meerkat
C	Yuna	200	0.85	chameleon
```

- **피치배율**: 1.00 = 원음, 0.85 = 15% 낮춤(길이 보존). 0.80~0.90이 실용 범위.
  0.75 미만은 음질이 뭉개진다.
- **음색 대비를 크게** 잡는다. 눈을 감고 들어도 누가 말하는지 구분돼야 한다.

### `input/timing.conf` — 타임라인 상수
```
COLD_OPEN=1.80      # 첫 대사 전 여백 (훅 이미지가 들어갈 자리)
OUTRO=2.80          # 마지막 대사 후 여백 (CTA/구독 카드)
MOUTH_FPS=12        # 입 모양 갱신 주기
TARGET_MIN=40
TARGET_MAX=50
```

### `input/readings.tsv` — 비한글 읽기 (선택)
TTS가 읽는 방식과 입 모양을 일치시킨다. `표기 ⇥ 한글읽기`

```
AI	에이아이
```

미등록 비한글이 있으면 02단계가 경고하고 중립 입모양으로 폴백한다.
숫자·영문 약어가 나오는 대본이면 **반드시 등록**해야 입이 맞는다.

### `input/characters/<화자ID>.json` — 캐릭터 (선택)
없으면 기본 프리셋으로 렌더된다. 파라메트릭 렌더용:

```json
{ "body": [232,178,108], "dark": [176,122,62], "eye": [40,32,28], "earStyle": "round" }
```

실제 아트를 쓸 때는 §7로.

## 4. 오디오 생성 방식 (01단계)

1. 줄별로 TTS 합성 → aiff
2. 피치 시프트 → wav (아래 필터 체인)
3. 길이 실측 → 타임라인 계산 (`start`, `end` 누적)
4. **화자별 풀길이 트랙** 생성: 자기 대사만 들리고 나머지는 무음
5. 마스터 믹스 (`amix` + `alimiter`)

### 피치 시프트 필터 (길이 보존)

```
aresample=44100,asetrate=44100*<p>,aresample=44100,atempo=<1/p>
```

**맨 앞의 `aresample=44100`을 빼면 안 된다.** macOS `say -o *.aiff`는 **22050Hz**로
출력한다. 그 위에 `asetrate=44100*p`를 걸면 기준이 어긋나 `(44100/22050)*p = 2p`배로
재생돼 **길이가 절반이 되고 피치가 내려가는 대신 올라간다**. 실측: 4.96s → 2.47s.

### 화자별 트랙이 왜 필요한가

립싱크 모델은 **프레임당 얼굴 하나만** 처리한다. 두 캐릭터가 한 화면에 있으면 립싱크가
엉뚱한 얼굴에 붙거나 깨진다. 따라서 캐릭터를 **각각 따로 렌더한 뒤 합성**해야 하고,
각 캐릭터에게 전체 길이의 트랙이 필요하다. 이는 세 립싱크 경로 모두에 해당한다.
→ **어떤 립싱크 MCP도 단독으로 완성 영상을 만들지 못한다.** 합성 단계는 항상 별도다.

## 5. 입 움직임 방식 (02단계) — 핵심 장치

### 5.1 원리

한글 음절은 `초성·중성·종성`으로 분해된다. **입 모양은 중성(모음)이 결정한다** —
자음은 입 모양에 거의 영향이 없다. 유니코드 산술로 완전 분해 가능하다:

```
code = 0xAC00 + (초성 × 21 + 중성) × 28 + 종성      (가 = U+AC00 … 힣 = U+D7A3)
중성 = ⌊(code − 0xAC00) / 28⌋ mod 21
종성 =  (code − 0xAC00) mod 28
```

### 5.2 입 모양 9종 (에셋 파일명 규약)

| 키 | 형태 | 대응 모음 |
|---|---|---|
| `A` | 크게 벌림 | ㅏ ㅑ |
| `E` | 옆으로 벌림 | ㅐ ㅔ ㅒ ㅖ |
| `EO` | 중간 벌림 | ㅓ ㅕ |
| `O` | 둥글게 | ㅗ ㅛ |
| `U` | 오므림 | ㅜ ㅠ ㅡ |
| `I` | 좁게 옆으로 | ㅣ |
| `M` | 완전히 닫힘 | 양순음 종성 / 무음 |
| `X` | 휴지(살짝 닫힘) | 구두점 |
| `R` | 쉼(기본 자세) | 발화 없는 구간 |

**이중모음은 2단계 전이**한다: ㅘ→`O,A` / ㅙ ㅚ→`O,E` / ㅝ→`U,EO` / ㅞ→`U,E` /
ㅟ ㅢ→`U,I`. 슬롯 프레임을 균등 분할해 순차 적용한다.

**양순음 종성**(ㅁ ㅂ ㅍ ㅄ ㄻ ㄼ ㄿ, 인덱스 `10,11,14,16,17,18,26`)은
모음 뒤에 `M`(닫힘)을 덧붙인다. → `금` = `U` → `M`

### 5.3 타이밍 배분

1. 텍스트를 **슬롯** 배열로 변환. 음절 = weight 1, 구두점 = weight 0.5(휴지)
2. 줄의 프레임 구간 `[start×fps, end×fps]`에 weight 비례 배분
3. 슬롯 내 다중 shape는 슬롯 프레임을 다시 균등 분할
4. 발화 끝 프레임에 `X` 1개 (말이 끊긴 느낌 방지)
5. 발화 없는 구간은 전부 `R`

한국어는 음절 등장성이 강해 **균등 배분만으로도 충분히 맞는다.** 단어 단위 강제 정렬
(whisper 등)은 정확도를 조금 올리지만 결정론성과 무의존성을 잃는다 — 권하지 않는다.

### 5.4 검증 방법

임의의 대본에 대해 아래로 확인한다. 기대와 실제가 어긋나면 매핑 버그다.

```bash
node -e '
const t=require("./build/timeline.json"), v=require("./build/visemes.json");
const L=t.lines.find(x=>x.n==="07");
const s=v.speakers.find(x=>x.id===L.spk);
const f0=Math.round(L.start*v.fps), f1=Math.round(L.end*v.fps);
let seq=[]; for(const r of s.mouth) for(let i=0;i<r.n;i++){const f=r.f+i; if(f>=f0&&f<=f1) seq.push(r.s);}
console.log(L.text, "→", seq.join(" "));'
```

검증된 실측 예 — `너 지금 색 바꿨어?`
```
EO EO  I I  U M  E E E  A A  U EO  EO EO EO  X X
너     지   금   색     바   꿨    어         ?
```
`금`의 종성 ㅁ이 입을 닫고(`U`→`M`), `꿨`의 이중모음 ㅝ가 `U`→`EO`로 전이한다.

### 5.5 눈 깜빡임

3~5초 간격, 2프레임. **입과 독립**으로 관리한다(말하는 중에도 깜빡인다).
시드는 화자 ID의 문자코드 합 + 7919 → 컴퓨터가 달라도 같은 패턴이 나온다.

## 6. 길이 맞추기 (40~50초)

01단계가 총길이를 계산해 목표 범위를 벗어나면 **exit 2 + 보정 지시**를 출력한다.
조절 우선순위:

1. **gap 총합** — 가장 안전하다. 대사 리듬이 변하지 않는다.
2. **COLD_OPEN / OUTRO** — 훅·CTA 여백
3. **rate** — 최후. `say -r`은 **이산 양자화**되어 미세 조정이 안 된다.
   실측: `-r 128`과 `-r 150`이 **동일 길이**(4.96s). 유효 단위는 대략 100/150/200/250.

분량 감각 (Yuna, `-r 200`, 피치 1.0 기준): 한국어 **약 8.2음절/초**.
45초 목표라면 발화 33초 + gap 8초 + 여백 4.6초 ≒ **270음절**이 적정.

## 7. 렌더 방식 (03단계) — ⛔ 합성 캐릭터 전용 경로

> **이 절은 `bin/00-build-characters` 로 캐릭터를 직접 그려 쓸 때의 경로다.**
> 외부에서 받은 아트(컷아웃)로 만드는 현행 작업에는 **쓰지 않는다.** → §8.6 / §11
> 카메라·컷 전환·지루함 방지 장치(§7 뒷부분)는 두 경로 모두에 유효하다.

Node가 raw RGBA 프레임을 생성해 **stdout으로 ffmpeg에 파이프**한다.
PNG 인코딩/디코딩, SVG 래스터라이저, 이미지 라이브러리에 의존하지 않는다.

```bash
ASPECT=9:16 NAME=shorts_01 node bin/03-render.mjs    # 1080x1920
ASPECT=16:9 NAME=long_01  node bin/03-render.mjs     # 1920x1080
```

### 카메라: 숏/리버스 숏 (오버 더 숄더)

두 캐릭터를 한 화면에 나란히 두면 정적이다. **화자만 정면으로 잡고, 상대는 화면 앞쪽에
뒷모습으로 크게 깔고, 화자가 바뀌면 컷을 친다.** 대화 영상의 기본 문법이다.

| 요소 | 규칙 |
|---|---|
| 정면(화자) | 중경. 눈·주둥이·입 전부. **립싱크 대상** |
| 뒷모습(청자) | 전경. 얼굴 요소 없음(뒤통수+귀/볏+어깨). 밝기 ×0.40 실루엣, 프레임 밖으로 잘림 |
| 컷 타이밍 | 새 화자의 `start − PRE_ROLL(0.18s)`. **말문이 열리는 순간을 보여줘야** 한다 |
| 배경 | 리버스 숏에서 **좌우 반전** → "반대편 카메라"로 읽힌다 |
| 푸시인 | 컷 안에서 서서히 확대 (초당 0.8%, 최대 +5%) — 정적인 느낌 방지 |

**180도 법칙 — 화면 좌우를 고정한다.** `slot 0` 은 언제나 화면 오른쪽,
`slot 1` 은 언제나 화면 왼쪽. 정면일 때도 뒷모습일 때도 같은 쪽이다.
이걸 어기면 컷마다 인물이 순간이동하는 것처럼 보여 공간 감각이 무너진다.

`slot` 은 `speakers.tsv` 의 등장 순서로 자동 부여된다. 바꾸려면 행 순서를 바꾼다.

| 비율 | 정면 위치 | 뒷모습 위치 | 자막 |
|---|---|---|---|
| 9:16 쇼츠 | 중앙에서 ±0.13W, 높이 0.40H | ±0.34W, 0.80H, 크기 ×1.55 | MarginV 300 |
| 16:9 롱폼 | ±0.17W, 0.46H | ±0.36W, 0.86H, 크기 ×1.64 | MarginV 60 |

전경 뒷모습이 자막을 가리면 `drawBack()` 의 `cy` 를 키워 더 아래로 내린다.

> 이 구조의 대가: 청자의 표정을 볼 수 없다. 리액션을 보여주고 싶은 순간에는
> 예외적으로 투 숏(둘 다 정면)을 쓰거나, 청자 쪽 컷을 한 박자 먼저 친다.

### 3인 이상일 때

현재 `drawBack()` 은 정면이 아닌 첫 번째 화자를 전경에 놓는다. 3인 이상이면
"직전 화자를 전경에 둔다" 로 바꾸는 게 자연스럽다 — 대화의 흐름을 따라간다.

### "입만 움직이면 3분 만에 지루해진다" — 필수 장치

성능 비용이 거의 없고, **"PPT에 입 달린 것"과 "볼 만한 영상"의 차이 전부**가 여기서 나온다.

| 장치 | 구현 | 값 |
|---|---|---|
| 아이들 바운스 | 몸통 Y축 사인파 | 주기 0.8s, 진폭 3px, 화자별 위상 오프셋 |
| 화자 강조 | 스케일 + 밝기 | 말하는 쪽 ×1.04 / 밝기 1.0, 듣는 쪽 ×0.97 / 0.72 |
| 눈 깜빡임 | 눈 → 가로 선 | 3~5초 간격, ±0.09s 윈도우 |
| 발화 끝 닫힘 | `X` 1프레임 | §5.3-4 |

추가 권장(미구현): 화자 전환 시 미세 줌/팬, 문장 경계 표정 교체, 숫자 카드 팝인,
귀·꼬리 트위치.

### 실제 아트로 교체하는 방법

`drawCharacter()`만 교체한다. 두 가지 길:

**구현된 방식 — 공통 viewBox 레이어 합성 (앵커 계산 불필요)**

`bin/00-build-characters.mjs` 가 캐릭터당 13개 레이어를 생성한다.
**모든 레이어가 같은 viewBox(400×480)를 쓴다.** 따라서 같은 픽셀 높이로 래스터화해
같은 좌표에 겹치면 자동으로 정렬된다 — 앵커 좌표를 따로 관리할 필요가 없다.

```
input/characters/<화자ID>/
  front_body.svg/.png          몸+머리+눈흰자+코 (눈동자·입 제외)
  front_eyes_open.svg  front_eyes_closed.svg
  front_mouth_{A,E,EO,O,U,I,M,X,R}.svg      ← §5.2 의 9개 키와 이름이 정확히 일치
  back.svg                     뒷모습 (얼굴 요소 없음)
  meta.json
```

래스터화는 `@resvg/resvg-js` (Rust, 알파 보존). 렌더러는 SVG 를 직접 읽어
필요한 크기로 래스터화하며, PNG 는 확인·전달용이다.

**푸시인은 이산 단계로 처리한다.** 매 프레임 재래스터라이즈는 비싸므로
`PUSH_STEPS=4` 단계를 미리 렌더해 놓고 골라 쓴다.

`input/characters/<ID>_sheet.png` 에 정면·깜빡임·뒷면·입모양 9종을 한 장으로
출력한다. **새 캐릭터를 만들면 이 시트를 먼저 눈으로 확인할 것.**

### 캐릭터 작도 시 실제로 걸린 문제

| 증상 | 원인 | 대응 |
|---|---|---|
| 날개가 귀처럼 보인다 | 부속물이 머리 높이에 있었다 | 몸통 하단으로 내리고 회전 각도를 키운다 |
| 벌어진 입이 각져 보인다 | 삼각형 path 로 입 안쪽을 그렸다 | 둥근 타원 2겹(어두운 안쪽 + 밝은 혀) |
| 형태가 배경/자기 몸에 묻힌다 | 크림색 캐릭터 = 저채도 단색 | **외곽선 필수** (`line` 색, 5px). 밝은 캐릭터는 반드시 |
| 코·입이 안 읽힌다 | 얼굴 대비 너무 작다 | 코는 얼굴폭의 9%, 입은 12% 이상 |
| `A`(최대 개구)가 다른 것과 구분 안 된다 | 개구 범위가 좁다 | 최대 개구를 부리/입 반폭 이상으로 |

### 배치: `input/placement.json`

캐릭터별 크기·위치를 비율로 정의한다. 캐릭터마다 크기를 다르게 줄 수 있다
(예: 아이 캐릭터는 작게).

```json
{ "P": { "tall": { "side": 1, "frontH": 0.48, "frontX": 0.14, "frontBottom": 0.68,
                   "backH": 0.85, "backX": 0.60, "backBottom": 1.15, "backDim": 0.40 } } }
```

- `side`: **+1 = 화면 오른쪽, −1 = 왼쪽.** 180도 법칙을 여기서 고정한다
- `frontH`/`backH`: 화면 높이 대비 캐릭터 높이 (1.0 초과 → 프레임 밖으로 잘림)
- `*Bottom`: 발끝 y 위치 (1.0 초과 → 아래로 잘림). 전경은 1.15 정도
- `backDim`: 전경 실루엣 밝기 배율

**⚠️ `backX` 는 레이어 폭이 아니라 "캐릭터 형태의 중심" 기준으로 잡아야 한다.**
캐릭터는 viewBox 안에서 여백을 갖기 때문에, 레이어 기준으로 30%를 보여도
실제 형태는 거의 안 보인다. **형태 중심을 프레임 경계 바로 밖(±0.10×폭)에** 두면
머리 반쪽이 전경으로 들어온다. 실측된 값이 `backX ≈ 0.60`(9:16) / `0.50`(16:9) 이다.

배치를 바꾼 뒤에는 반드시 컷 양쪽 프레임을 추출해 **전경이 화자 얼굴을 덮지 않는지**
확인한다.

**대안 (프로덕션 확장 시): Remotion** — React 기반이라 표정 전이·카메라 모션·
자막 애니메이션이 훨씬 쉽다. `build/visemes.json` 을 props 로 넘기면
이 문서의 타임라인 규약을 그대로 쓸 수 있다.

### 캐릭터 이미지 요구사항 (생성형 립싱크에 넣을 경우)

- **정면**, 얼굴이 프레임의 50% 이상
- **입이 닫힌 상태**로, 윤곽이 뚜렷하게
- 눈이 보이고 정면 응시
- **단일 캐릭터**, 배경 단순 또는 투명 (합성은 나중에)
- 카툰이어도 얼굴 구조가 뚜렷해야 한다 — 모델이 입을 찾아야 한다

## 8. 대본·플롯 구성 방식

토픽이 바뀌어도 통하는 틀.

### 8.1 2인 대화 캐스팅 원칙

- **질문자** = 시청자 대변인. 시청자가 궁금할 것을 대신 묻는다. 순진해도 된다.
- **답변자** = 권위 + 온기. 설명하지만 가르치려 들지 않는다.
- **캐릭터가 주제의 은유이면 훨씬 강하다.** (예: 상황 인식 → 경계 서는 미어캣 +
  관찰되면 색이 변하는 카멜레온. 답변자가 설명자이면서 동시에 살아있는 반례가 된다)
- 목소리·캐릭터는 **채널 정체성**이다. 한 번 정하면 바꾸지 않는다.

### 8.2 구조 (40~50초 기준, 11줄 전후)

| 구간 | 줄 | 역할 |
|---|---|---|
| 훅 | 1~2 | 첫 1.5초에 긴장을 만든다. 질문자의 결핍/오해로 시작 |
| 전개 | 3~6 | 한 번에 한 가지만. 답변자가 상식을 뒤집는다 |
| 전환 | 7 | **시연 지점.** 말로 설명한 것을 화면에서 보여준다 (최고 어텐션 구간) |
| 정리 | 8~11 | 결론을 한 문장으로 압축. 마지막 줄이 가장 짧아야 한다 |

### 8.3 작성 규칙

- 한 줄 = **한 호흡**. 25음절을 넘기면 자막이 3줄로 넘어가 가독성이 깨진다.
- 질문자 줄은 짧게(5~20음절), 답변자 줄은 길게(20~35음절). 리듬이 생긴다.
- **숫자·고유명사는 `readings.tsv`에 등록**한다. 안 하면 입이 어긋난다.
- 마지막 줄은 **명제로 끝낸다.** 요약이 아니라 주장.
- 전환 지점(7번)에 gap 1.0~1.4초를 준다. 침묵이 강조 장치다.

### 8.4 사실성이 중요한 주제라면 (세무·의료·법률 등)

`script.tsv`에 감수 상태를 두고 **렌더 전에 하드 게이트**를 건다.
`review_status != approved` 면 03단계가 실행되지 않게 한다. 자동 생성은 오류도 배치로
나간다. 기준연도 표기와 "일반적 정보 제공" 고정 자막을 템플릿에 박아둔다.

## 8.5 두 가지 영상 포맷

같은 파이프라인에서 `MODE` 로 전환한다.

| | `MODE=dialogue` | `MODE=narration` |
|---|---|---|
| 화자 | 2인 교대 | 1인 고정 (`NARRATOR=<ID>`) |
| 화면 | 화자는 **앞면**(립싱크), 청자는 **뒷면** | 화자만 앞면, 위치 고정 |
| 배경 | 화자에 따라 2종 교대 | 대사별 지정 (script.tsv 5번째 열) |
| 좌우 위치 | `placement.json` 의 `side` 로 고정 (180도 법칙) | 해당 없음 |

**대화 배경 2종은 같은 장소의 다른 벽면이어야 한다.** 팔레트·바닥선·창틀 두께를
공유하면 컷이 바뀌어도 "같은 방"으로 읽힌다. 완전히 다른 장소를 쓰면 두 사람이
각자 다른 곳에 있는 것처럼 보인다.

**나레이션 배경은 내용의 비트를 따라간다.** 상승 → 레버리지 → 급락 → 마진콜 →
매각 → 결말. 배경이 곧 자막 없는 설명이므로, 한 배경에 한 가지 개념만 담는다.
지정하지 않은 줄은 직전 배경을 이어받는다.

### 대화 포맷의 카메라: 오버더숄더 원근

**"평면 2D 아트"와 "카메라 원근"은 별개다.** 아트는 색면으로 평평하게 유지하면서,
원근은 **크기·크롭 차이만으로** 만든다. 그라디언트 음영·블러·3D 변형은 쓰지 않는다.

카메라는 두 위치만 쓴다:

| 화자 | 카메라 위치 | 전경(크게, 잘림) | 중경(작게, 정면) |
|---|---|---|---|
| 질문자 | **답변자 뒤** | 답변자 뒷모습 | 질문자 앞모습 |
| 답변자 | **질문자 뒤** | 질문자 뒷모습 | 답변자 앞모습 |

실측 비율 (9:16):
- 전경(뒷모습): 화면 높이의 **0.78~0.86**, `backBottom 1.18`(아래로 잘림), `backX 0.41~0.44`
- 중경(앞모습): 화면 높이의 **0.28~0.32**, `frontBottom 0.62`, `frontX 0.17`
- 전경만 평면 배수로 어둡게 (`backDim 0.55`) — 시선을 화자로 보낸다. 그라디언트 아님

**180도 법칙**: `side` 로 좌우를 고정한다. 한 캐릭터는 앞모습이든 뒷모습이든
**항상 같은 쪽**에 있어야 한다. 어기면 컷마다 인물이 순간이동하는 것처럼 보인다.

**배치 후 반드시 컷 양쪽 프레임을 추출해 전경이 화자 얼굴을 덮지 않는지 확인한다.**
전경 위치는 레이어 폭이 아니라 **캐릭터 형태의 중심** 기준으로 계산해야 한다(§7).

## 8.6 ⭐⭐⭐ 최종 결론: **한 그림 세트 안에서만 눈·입을 갈아끼운다**

여러 방법을 다 돌아 여기에 도달했다. **앞으로는 이것부터 시도할 것.**

원칙은 두 줄이다.

1. **서로 다른 그림끼리 이목구비를 옮기지 않는다.** (컷아웃 ↔ 장면 이미지 금지)
2. **표정 이미지를 통째로 교체하지 않는다.** 항상 하나의 베이스에서 마스크 안쪽만 덮어쓴다.

### 왜 "장면 이미지를 베이스로" 가 틀렸나 (앞 판단의 폐기 기록)

한동안 "완성 장면 이미지를 베이스로 쓰고 컷아웃에서 입·눈만 떼어 이식한다"를
정답으로 잡고 있었다. 배경·책상·구도가 이미 맞아 있어 매력적으로 보였다.
**실제로 만들어 보면 실패한다.**

- 두 그림은 별개 생성물이라 머리 대 이목구비 비율이 미세하게 다르다.
  동공 두 점으로 상사변환을 맞추면 눈은 맞지만 **입이 프레임마다 몇 px 씩 흔들린다.**
- 주둥이 털 음영·볼터치의 계조가 달라 이식 경계에 **얼룩**이 남는다.
- 사용자 판정: "너구리 입 위치도 자꾸 바뀌고, 토끼 입과 볼터치도 부자연스러워."

정렬을 아무리 정교하게 해도(동공 검산까지 통과시켜도) 이 문제는 남는다.
**원인이 정렬 오차가 아니라 두 그림이 서로 다른 그림이라는 사실 자체이기 때문이다.**

### 대신 이렇게 한다

제공 자산은 보통 **표정별 클로즈업 컷아웃 세트**다. 이 세트끼리는 같은 원본에서
파생돼 **이미 픽셀 단위로 정렬돼 있다.** 실측으로 먼저 확인한다:

```bash
node bin/tool-bbox.mjs cut/*.png     # 알파 bbox 가 1~2px 이내로 같아야 한다
# close_01_기본  bbox x194-1213 y78-927
# close_02_설명  bbox x194-1213 y78-927   ← 동일 = 확대·회전 없이 좌표 그대로 복사 가능
```

정렬돼 있으므로 **보간이 아예 필요 없다.** 좌표 그대로 복사하면 끝이고,
따라서 흔들릴 여지가 물리적으로 없다.

```bash
# 1) 차이 영역이 눈/입으로 분리되는지 먼저 본다 (덩어리별 bbox 를 뽑는다)
node bin/tool-diffmap.mjs cut/기본.png cut/설명.png
#    덩어리 6364px x576-832 y668-764   ← 입
#    덩어리 1639px x581-644 y351-437   ← 눈 (표정 차이)

# 2) 하나의 베이스에서 마스크 안쪽만 덮어써 조합을 만든다
node bin/13-graft-aligned.mjs --base 기본.png --out N_경고_open.png \
     --graft 경고.png:390,290,1030,620      `# 눈 ROI` \
     --graft 설명.png:540,640,870,800       `# 입 ROI`
```

### ⚠️ 표정 이미지를 통째로 갈아끼우지 말 것

"기본 ↔ 설명" 두 장을 번갈아 재생하면 입은 움직이지만 **캐릭터 전체가 지글거린다.**
두 장의 외곽선 안티에일리어싱이 서로 달라서다(실측: 전 화면에 산발적으로
너굴 1,600px / 토리 5,100px 차이). 눈에 잘 안 띄지만 영상으로 보면 "부자연스럽다"고
느껴지는 정체가 이것이다.

→ **항상 하나의 베이스 이미지에서 출발**해 마스크 안쪽만 덮어쓴다.
그러면 마스크 밖은 **바이트 단위로 동일**해 지글거림이 원천적으로 없다.

### ⚠️ 마스크는 사각형이 아니라 **차이 성분(connected component)**

사각형이면 경계가 다른 부위를 자른다. 실제로 토리는 눈 상자와 입 상자가 x 축에서
겹쳐(눈 x456-633, 입 x620-756) 어떤 사각형을 잡아도 한쪽이 깨진다.

→ 차이 픽셀을 라벨링해 **덩어리 단위**로 채택한다. 채택 기준은 두 개다:
- 덩어리 크기 ≥ 150px (그림 전체에 흩어진 안티에일리어싱 잡음을 버린다)
- 덩어리 **bbox 중심이 ROI 안**에 있을 것 (걸치기만 한 남의 부위를 배제한다)

채택 후 4~6px 팽창(경계를 "두 그림이 같은" 영역까지 밀어낸다) → 3회 블러 페더.
같은 영역이므로 번짐이 해롭지 않고, 경계선이 보이지 않는다.

### 컷아웃이 잘려 있으면 — ⚠️ **먼저 무엇이 잘렸는지 알파 행 프로파일로 확인한다**

눈으로 보면 "머리 위가 통째로 잘렸다"고 판단하기 쉽다. **실측하면 대개 훨씬 적다.**

```bash
node bin/tool-prof.mjs cut/기본.png     # 행별 알파 구간
#  y=  0   288-456   952-1119     ← 구간이 둘뿐 = 잘린 것은 **귀 두 개**
#  y= 10   …638-662…              ← 가운데 털끝이 이때 나타남 = 정수리는 온전
#  y= 50   280-1127               ← 머리가 하나로 합쳐짐
```

너굴은 정수리가 멀쩡하고 **귀 끝 두 군데만** 잘려 있었다. 복원 범위를 최소로 잡을수록
티가 안 난다. 크게 잡으면 없던 문제를 만든다.

### ⚠️ 잘린 부분을 **장면 이미지에서 떼어 오면 안 된다** (실패 기록)

`bin/10-repair-crown.mjs` 로 장면에서 정수리를 떼어 이어 붙였다. **실패했다.**

- 장면 캐릭터와 클로즈업 컷아웃은 별개 생성물이라 **머리 비율이 다르다.**
  동공 두 점으로 상사변환을 맞춰 겹쳐 보면 컷아웃 머리가 장면 머리보다 넓고
  귀 위치도 어긋난다(실측: 아래 진단 참조).
- 그 상태로 이어 붙이면 이음매에서 **두 모양이 겹쳐 보인다.** 교차 페이드(blend)를
  주면 두 털 무늬가 반투명으로 포개져 오히려 더 나빠진다.
- 배경을 다각형으로 잘라내면 귀 주변에 **각진 배경 조각**이 남는다.

사용자 판정: "너구리 머리 위쪽이 두 모양이 겹쳐보여 계속."

**진단 방법** — 붙이기 전에 두 그림을 겹쳐 실루엣이 맞는지 먼저 본다:

```bash
# 장면을 컷아웃 좌표계로 변환해 깔고, 컷아웃을 초록 반투명으로 얹는다
# 초록이 장면 실루엣 밖으로 삐져나오면 그 조합은 절대 안 맞는다 → 포기할 것
```

### 잘린 부위는 **컷아웃 자신의 픽셀로** 재구성한다

`bin/16-rebuild-ears.mjs` — 잘린 단면 아래의 단면들을 위로 올리면서 가로로 좁혀
끝을 만든다. 모든 픽셀이 같은 그림에서 오므로 색·질감이 어긋날 수가 없다.

```bash
node bin/16-rebuild-ears.mjs cut/기본.png ears/기본.png \
     --ears "288,456 952,1119" --k 45 --ratio 1.074
```

⚠️⚠️⚠️ **귀는 좌우 대칭으로 좁아지지 않는다. 중심을 고정하면 끝 방향이 틀린다.**
이게 "귀 끝이 이상하다"의 마지막 원인이었다. 원화의 완전한 귀를 6배 격자로 얹어
**좌·우 경계를 따로** 추적하면 이렇게 나온다(너굴 실측):

```
바깥(외측) 경계 … 거의 수직        (-0.18 px/행)
안쪽(내측) 경계 … 크게 안으로 쓸림 (+1.43 px/행)
```

즉 **안쪽에서만 좁아지고, 끝은 바깥쪽으로 치우친다.** 중심이 W0 의 약 10%(≈17px)
바깥으로 이동한다. 두 귀가 바깥으로 벌어지는 실루엣이 나와야 정상이다.

→ 폭만 맞추지 말고 **폭 + 중심 이동을 같이** 프로파일 테이블로 넣는다:

```js
const PROF_F = [0.000, 0.295, 0.593, 0.738, 0.858, 0.928, 1.000]; // 끝까지 비율
const PROF_W = [1.000, 0.888, 0.763, 0.586, 0.379, 0.237, 0.000]; // 폭 / W0
const PROF_C = [0.000, 0.042, 0.077, 0.092, 0.106, 0.100, 0.100]; // 중심 바깥이동 / W0
```

폭만 맞춘 대칭 모양들은 전부 반려당했다:
- `W0·sqrt(1-(k/K)²)` → 위가 평평한 돔이 얹혀 **여우 귀**처럼 길어졌다
- `W0·(1-k/K)^0.8`   → 끝이 **뾰족한 삼각형**이 됐다
- 중심고정 타원        → 폭은 맞는데 **끝이 가운데로 서서** 방향이 틀렸다

⚠️ 귀 중심의 좌우 이동을 **안쪽 가장자리로 재면 안 된다.** 안쪽은 정수리 털이
다리를 놓아 실제보다 크게 벌어진 것처럼 측정된다(실측 1.0px/행 → 원화에서는 거의 0).

⚠️ **바깥 윤곽선 띠(RIM)는 눌러 담지 말 것.** 단면을 통째로 균등하게 누르면
윤곽선까지 같이 눌려 끝에서 **선이 사라지고 매끈한 플라스틱 덩어리**처럼 보인다(실측 실패).
가장자리 RIM px(기본 6)는 원본 폭 그대로 옮기고 **안쪽만** 눌러 선 굵기를 지킨다.

⚠️ **뒤통수처럼 매끈한 면에는 띠 모델을 쓰지 말 것**(`--noband`). 귓속 구조가 없어
닫혀가는 띠 경계가 **대각선 주름**으로 드러난다. 그런 그림은 균등 축소 + 강한 흐림이 낫다.

⚠️ **SKIP 은 이음선에 가로 줄을 만든다.** k=0 에서도 그만큼 아래 단면을 가져오기 때문이다.
지저분한 윗행은 SKIP 이 아니라 **원본을 미리 crop 해서 버릴 것.**

⚠️ **프로파일 끝 구간이 직선이면 각진 면이 생긴다.** 무늬 없는 면에서 특히 눈에 띈다.
끝 근처는 `W ∝ sqrt(1-f)` 가 되도록 점을 촘촘히 넣어 둥글게 마감한다.

⚠️ **흐림 탭 수를 고정하지 말 것.** 반경이 커질 때 계단(에일리어싱)이 생겨 역시
대각선 주름으로 보인다. 반경에 비례해 탭을 늘린다.

⚠️ **마지막에 내부 후처리 흐림**(`--post`)을 건다. 귓속이 닫히고 나면 크림 띠 두 개가
맞닿는데 원본에서 두 띠의 톤이 달라 **끝으로 수렴하는 주름**이 남는다.
알파 경계에서 6px 안쪽만 대상으로 해야 윤곽선이 뭉개지지 않는다.

⚠️⚠️⚠️ **귀는 폭 하나로 재구성할 수 없다. 띠마다 제 궤적을 줘야 한다.**
단면을 통째로 균등하게 눌러 올리면 **귓속 어두운 부분이 끝까지 따라 올라가** 부자연스럽다.
행마다 띠(바깥선 / 크림 / 귓속 / 크림 / 안쪽선)를 측정하면 이렇게 나온다(너굴 왼쪽 귀):

```
y     바깥선     크림      귓속(어두움)   크림      안쪽선
 0   288-294  295-311   312-354(43)  355-428  429-456
24   282-285  290-297   298-394(97)  395-440  445-470
```

귓속 반폭이 1.09px/행로 줄어 **절단면 위 20px 에서 닫힌다.** 원화에서도 귀 끝은
크림과 윤곽선만 남는다. 그래서 목표 매듭 6개(바깥끝·윤곽선끝·귓속시작·귓속끝·안쪽띠·안쪽끝)를
만들고 원본 매듭 6개와 **구간별 선형으로** 잇는다. 윤곽선은 굵기 유지, 안쪽 띠는 폭에 비례,
귓속은 제 기울기대로 닫힌다.

⚠️ **끝으로 갈수록 띠 안에서 흐리게** 한다(`--smooth`). 단면을 그대로 밀면 원본의 미세한
명암이 **세로 줄무늬**로 남는다. 원화의 귀 끝은 톤이 뭉개진 매끈한 덩어리다.
흐림은 반드시 **그 띠 안으로 제한** — 띠를 넘으면 윤곽선이 번진다.

⚠️⚠️ **표정마다 따로 재구성하지 말 것.** 띠 검출은 안티에일리어싱에 민감해 한 장만
실패해도 그 표정의 귀가 달라진다(실측: `close_02_설명` 좌측 귀 검출 실패 → 기본과 2,086px 차이
→ **입이 열릴 때 귀가 같이 움직인다**). `bin/16b-sync-ears.mjs` 로 기준 한 장에서 복사해
강제 동기화하고, 표정 간 차이 지도에 **귀 영역 덩어리가 없는지** 반드시 확인한다.

⚠️⚠️⚠️ **이음선 위에 아래 무늬를 다시 재생하면 안 된다.**
"이어지는 부분과 그 위가 이상하다"의 원인이다. 끝으로 갈수록 더 아래 단면을 끌어올리면
(`--depth 14` 같은 설정) **귓속 어두운 부분이 이음선 위·아래에 두 번** 나타난다(8배 확대에서 명확).
→ `--depth 0`: **절단면 단면 하나만** 가로로 눌러 위로 잇는다. 띠(외곽선·크림·귓속)가
   끝을 향해 자연스럽게 수렴하고, 중복이 원리적으로 생길 수 없다.

⚠️ **폭은 행의 아래쪽 모서리에서 잰다** (`(k-0.5)/K`). 위쪽 모서리에서 재면
   이음선 첫 행이 2px 좁아져 턱이 진다.

⚠️ **윤곽선 마감은 이음선 쪽으로 0 까지 빼야 한다**(`--strokefade`, 기본 12행).
   이음선까지 선을 그으면 원본 구간만 갑자기 진해져 가로로 턱이 생긴다.

⚠️⚠️⚠️ **끝을 반드시 윤곽선으로 둘러 마감할 것 (`--stroke`, 기본 5px).**
이것 하나가 "귀 끝이 이상하다"의 진짜 원인이었다. 세 번 반려당하고서야 찾았다.

타원은 apex 근처에서 폭이 sqrt 로 급감한다. 정수 행으로 래스터화하면
**맨 윗행이 30px 폭으로 뚝 끊기고, 그 위쪽 경계에는 선이 없다.**
좌우 끝에는 원본에서 옮겨온 윤곽선이 있지만 **위쪽에는 없으므로**,
크림색 단면이 배경에 그대로 노출돼 "잘린 것 같기도 하고 뭉툭하기도 한" 모양이 된다.
(5배로 확대해야 보인다. 1:1 로는 "뭔가 이상한데" 수준으로만 느껴진다.)

→ 재구성 영역의 **알파 실루엣 경계**를 따라 윤곽 색을 5px 두께로 두른다.
   윤곽 색은 near-black 이 아니라 **원본 귀 바깥쪽 몇 픽셀의 평균**(실측 rgb(85,64,56))을 쓴다.
   임의의 검정을 쓰면 그림체와 어긋난다.

→ 폭은 행 중심이 아니라 **행의 위쪽 모서리**에서 잰다(`k+0.5`). 중심에서 재면
   맨 윗행이 실제보다 넓게 남는다.

⚠️⚠️ **K(귀 끝 높이)는 확대해서 정하면 안 된다. 실제 영상 배율 1:1 로 판단하라.**

그리고 **"끝이 이상하다"는 지적이 높이 문제인지 윤곽선 문제인지 먼저 분리하라.**
여기서 그걸 안 하고 높이만 계속 건드려 세 번 왕복했다:

| 시도 | 결과 |
|---|---|
| K45, 윤곽선 눌림 | "귀 끝이 이상해" — 원인은 **높이가 아니라 사라진 윤곽선**이었다 |
| K24, 윤곽선 보존 | "귀가 눌려있다" — 높이를 과하게 깎았다 |
| **K40, 윤곽선 보존** | 통과 |

**K 를 구하는 법** (감으로 정하지 말 것):
- 폭 곡선으로 타원을 풀려는 시도는 **여기선 실패한다.** 보이는 구간(절단면 아래 12행)의
  폭이 169→190 으로 거의 **직선**이라 2차항이 0 에 가깝다. 곡률 정보가 없다.
  (13행부터는 정수리 털이 다리를 놓아 205 로 튀므로 더 못 쓴다.)
- 대신 **원화의 귀 옆면 프로파일**에 절단면의 폭과 기울기를 맞춰 배율을 푼다.
  너굴 실측: 절단면 W0=169, 기울기 1.75px/행 → 원화에서 같은 비를 갖는 지점 k*≈31.7,
  배율 s=1.614 → 잘린 높이 = k*·s ≈ **51px**. 여기에 실제 크기 확인을 거쳐 40 으로 확정.

```bash
# 배경 위에 실제 배율로 얹어 확대 없이 본다
ffmpeg -i shelf.png -i ears.png -filter_complex \
  "[0:v]scale=1080:1920:...[bg];[1:v]scale=<실제폭>:-1[c];[bg][c]overlay=X:Y,crop=1080:210:0:600" out.png
```

⚠️ **컷아웃 맨 위 몇 행은 대개 지저분하다** — 순백 얼룩, 너덜한 안티에일리어싱.
그대로 재구성하면 끝까지 늘어나 **하얀 쐐기와 가로 줄무늬**가 된다(실측).
두 가지로 막는다.

1. 흰 얼룩은 **알파를 0 으로 지우지 말고 아래쪽 성한 색으로 메꾼다.**
   지우면 그 자리가 구멍이 되어 재구성한 귀가 **찢어진다**(실측).
   (`--despeck`, 기본 켜짐. 판정: 알파 있음 + `min(r,g,b)>225` + `max-min<14`)
2. 그래도 남으면 **맨 위 N 행을 아예 잘라내고** 그 아래를 절단면으로 삼는다.
   ```bash
   ffmpeg -i cut.png -vf "crop=W:H-10:0:10" src.png   # 위 10행 폐기
   node bin/16-rebuild-ears.mjs src.png out.png --ears "..." --skip 4
   ```

⚠️ 단면을 **정수 행으로 고르면 한 행이 여러 출력 행에 반복돼 가로 줄무늬**가 생긴다.
세로도 보간할 것(구현됨). `--skip` 으로 위쪽 지저분한 행을 건너뛴다.

⚠️ **여러 표정 파일에 `--ears` 를 똑같이 주어야** 결과물의 알파 bbox 가 같아진다.
(실측 확인: 네 장 모두 `x194-1213 y1-812` 로 일치)

⚠️ 재구성으로 이미지 높이가 바뀌면 **13-graft-aligned 의 ROI y 값과 배치 JSON 의
`content` 를 같은 양만큼 옮겨야 한다.** 잊으면 눈·입 마스크가 엉뚱한 곳을 잡는다.

### 배경·책상 판 만들기 (배경이 없는 컷아웃 세트일 때)

컷아웃 세트에는 배경이 없다. 장면 이미지에서 **깨끗한 구간만** 떼어 판을 만든다.

**책장 배경판** — 캐릭터 머리 위쪽은 보통 전 폭이 깨끗하다. 그 띠를 잘라
**상하 미러 타일링**으로 늘린다. 세로로 그냥 늘리면 바인더가 막대처럼 뭉개지는데,
미러는 선반 가로줄이 선반으로 그대로 읽혀 이음매가 보이지 않는다.

```bash
ffmpeg -i scene.png -vf "crop=768:345:0:0" band.png
ffmpeg -i band.png -i band.png -filter_complex \
  "[0:v]split=2[a][b];[b]vflip[bf];[1:v]split=2[c][d];[d]vflip[df];\
   [a][bf][c][df]vstack=4,scale=1080:-1,gblur=sigma=3" shelf.png
```
합성 때 `gblur=sigma=5~6, eq=brightness=-0.06` 을 더 건다. 배경이 뒤로 물러나
캐릭터가 앞으로 나온다. ⚠️ 블러는 **배경에만**. 캐릭터에 걸면 안 된다.

**책상판** — 소품(계산기)과 캐릭터를 피한 좁은 구간을 잘라 가로로 늘린다.
나뭇결이 거의 가로선이라 **가로 확대는 5배까지도 티가 안 난다.** 세로는 위쪽
모서리 60px 만 원본 배율로 두고 아래만 늘려야 모서리 선이 두꺼워지지 않는다.

⚠️ **책상은 한 장이 아니라 두 장이다. 윗면(수평)과 앞판(수직)으로 나눈다.**
한 장으로 깔면 화면 아래 40%가 균일한 나무판이라 **책상이 아니라 벽으로 보인다.**
나누면 두 가지를 동시에 얻는다.
- 모서리 선 하나로 원근이 생겨 진짜 책상으로 읽힌다
- 뒤통수 캐릭터를 **앞판 뒤**에 두면 하반신이 잘려
  "테이블 칸막이 뒤에 서 있는" 그림이 된다 (§ 오버더숄더 기하 참조)

윗면은 먼쪽(위)이 어둡고, 앞판은 전체가 더 어두우며 **윗모서리만 빛을 받는다.**

```bash
# 윗면: 먼쪽이 어둡다
geq=r='r(X,Y)*(0.64+0.36*min(1,Y/300))':...:a='alpha(X,Y)'
# 앞판: 더 어둡게 + 윗모서리 하이라이트
geq=r='r(X,Y)*(0.50-0.10*min(1,Y/430))':...:a='alpha(X,Y)'
drawbox=x=0:y=0:w=1080:h=5:color=0xE8C08A@0.9:t=fill
```

⚠️⚠️ **`geq` 에 `a` 식을 안 주면 알파가 0 이 된다.** 그런데 `overlay` 의 기본
`format=yuv420` 이 알파를 버려서 **화면에는 멀쩡히 그려진다.** 즉 버그가 조용히 숨는다.
다른 경로(미리보기, PNG 합성, 다른 필터)로 가는 순간 판 전체가 사라진다.
반드시 `a='alpha(X,Y)'` 를 붙일 것. 확인:

```bash
ffmpeg -v error -i plate.png -vf "format=rgba,crop=1:1:540:200" -f rawvideo -pix_fmt rgba - | xxd -p
# 끝 두 자리가 ff 여야 한다. 00 이면 알파가 죽은 것이다.
```

### 배치는 **알파 bbox 기준**으로 지정한다

이미지 여백은 그림마다 다르다. 여백 기준으로 좌표를 주면 캐릭터가 컷마다 어긋난다.
`contentLeft / contentTop / width` 를 **캐릭터 외곽(알파 bbox)** 기준으로 주고,
합성기가 이미지 좌표로 환산한다(`bin/14-compose-shot.mjs`).

#### `input/layout_*.json` 스키마 (실제 사용값)

```jsonc
{
  "bg":   "build/cu/plate/shelf.png",
  "bgFx": "gblur=sigma=6,eq=brightness=-0.07:saturation=0.86",   // 배경만 흐리게(심도)
  "desk":  { "img": ".../desk_top.png",   "top": 1090, "fx": "eq=brightness=-0.02" },
  "apron": { "img": ".../desk_front.png", "top": 1360 },          // 책상 앞판(수직면)
  "chars": {                                                      // 말하는 캐릭터
    "N": { "dir": "build/cu/v2", "exprs": ["기본","경고"],
           "content": [194, 0, 1213, 807],   // 원본 알파 bbox [x0,y0,x1,y1] ← tool-bbox 로 실측
           "width": 760,                     // 화면에서 캐릭터 외곽의 가로 폭
           "contentLeft": 280, "contentTop": 503 },
    "T": { "dir": "build/cu/v2", "exprs": ["기본","놀람"],
           "content": [227, 59, 1147, 751], "width": 720,
           "contentLeft": 300, "contentTop": 560 }
  },
  "back": {                                                       // 화자별 **상대방 뒤통수**
    "N": { "img": ".../T_뒤통수.png", "content": [400,84,974,726],
           "width": 810, "contentLeft": -160, "contentTop": 1330,
           "fx": "eq=brightness=-0.14:saturation=0.85:contrast=0.95" },
    "T": { "img": ".../N_뒤통수.png", "content": [195,0,1213,800],
           "width": 1030, "contentLeft": 500, "contentTop": 1330, "fx": "…" }
  }
}
```

- `exprs` 의 이름은 `{화자}_{표정}_{closed|open}.png` 파일명과 일치해야 한다.
- `content` 를 **직접 적지 말고 `tool-bbox` 로 뽑아 넣는다.** 귀 복원 등으로 이미지 높이가
  바뀌면 이 값과 `contentTop` 을 **같이** 고쳐야 한다(안 고치면 캐릭터가 위아래로 튄다).
- 클로즈업은 `back` 이 없다. 나머지는 동일하다.

### 오버더숄더 기하 — 뒤통수는 **맨 앞**이다

레이어 순서:

```
배경 → 화자 → 책상 윗면 → 책상 앞판 → 뒤통수
```

⚠️ **뒤통수를 앞판 뒤에 두지 말 것.** 하반신이 앞판에 잘려 "칸막이 뒤에 숨은" 그림이
되는데, 그건 오버더숄더가 아니다. 칸막이는 **뒤통수에 가려져야** 한다
(캐릭터가 칸막이 앞에 서 있는 것처럼). 실패 판정: "칸막이는 캐릭터 뒷모습에 가려있어야지."

**뒤통수 비중은 레이어가 아니라 크기·위치로 줄인다.** 화면 밖(아래 + 옆)으로 밀어내면
가까이 있어 커 보이면서도 차지하는 면적은 작다. 실측 조정:

| | 폭 | 화면 점유 |
|---|---|---|
| 처음 (너무 큼) | 950 | 화면의 30%+ |
| 1차 축소 | 780 | 18% |
| 최종 | 700~900, 옆·아래로 잘림 | 13~14% |

제약은 하나만 남는다:

```
뒤통수 윗선 > 화자 입 아래끝     (얼굴을 가리면 절대 안 된다)
```

⚠️ **뒤통수 에셋의 알파 행 프로파일을 먼저 떠서** 어디까지 보일지 정한다.

```bash
node bin/tool-prof.mjs T_뒤통수.png 40
#  y=120~200  구간 둘   = 귀
#  y=240~440  하나      = 머리
#  y=440~600  가장 넓음 = 몸통
#  y=720      구간 둘   = 발     ← 화면 안에 들어오면 실패(책상 위에 선 것처럼 보인다)
```
화면 아래로 잘리는 양을 발이 확실히 빠지도록 잡는다.

⚠️ 전경은 카메라에 가까우므로 `eq=brightness=-0.14` 정도로 **어둡게** 깐다.

## 8.7 ⛔ 폐기된 초기 시도 (`09-render-static`) — 실패 기록으로만 읽을 것

> **여기 적힌 지시를 그대로 실행하면 사용자가 이미 반려한 결과가 나온다.**
> 특히 "잘린 단면을 디자인 요소(띠)로 가린다" 는 **머리 위 검은 막대**로 반려됐고,
> "책상을 키워 절단면을 덮는다" 는 **벽처럼 보이는 책상**으로 반려됐다.
> 현행 해법은 §8.6(귀 재구성 + 책상 윗면/앞판 분리)이다.
> 아래는 왜 그 길이 막혔는지의 기록이다.

가장 중요한 교훈이다. 생성형 립싱크(Flyworks 등)는 매 프레임 얼굴을 **재생성**한다.
그 과정에서 **캐릭터의 위치와 크기가 미세하게 흔들리고**, 클립마다 색·질감이 달라진다.
표정 클립을 갈아끼우면 그 흔들림이 겹쳐 어색해진다. 색을 맞추고 디졸브를 걸어도
근본 원인은 남는다. 실제로 이 문제를 잡느라 다음을 전부 시도했고 전부 부분적이었다:

- 평균 게인 색보정 → 대비 차이가 남음
- 평균+대비 선형 정규화 → 색은 맞았지만 위치·크기 흔들림은 그대로
- 0.5초 디졸브 → 흔들림이 디졸브 중에 더 드러남

**해법: 표정 스틸을 고정 좌표·고정 배율로 합성하고, 눈과 입만 바꾼다.**

### 전제: 표정 이미지끼리 눈·입 외에는 동일해야 한다

같은 캐릭터의 표정 이미지 차이를 재보면(불투명 영역만) **눈 영역과 입 영역에만**
차이가 있고 그 밖은 픽셀 단위로 동일하다. 그래서 입 영역만 잘라 덮어도 이음새가
생기지 않는다. 확인 방법:

```bash
# 격자 밀도 지도로 차이가 어디에 몰렸는지 본다 (눈 행 / 입 행에만 있어야 정상)
node /tmp/dmap.mjs 기본.png 설명.png "기본→설명"
```

⚠️ **알파 bbox 가 몇 px 만 어긋나도 표정 전환 시 캐릭터가 움직이는 것처럼 보인다.**
`bin/08-align-expressions.mjs` 로 공통 bbox 에 평행이동해 맞춘다(실측: 토리 −5~−6px).

### `bin/09-render-static.mjs`

```bash
MODE=dialogue node bin/09-render-static.mjs --config input/static_dialogue.json --name OUT
```

- **입**: 발음 세기를 임계값(0.40)으로 갈라 **열림 / 닫힘 둘 중 하나로만** 그린다.
  `OPEN = {A:1.0, O:0.82, EO:0.72, U:0.5, E:0.45, I:0.25, X:0.08, M:0, R:0.04}`
  → ㅏㅗㅓㅜㅔ 는 열림, ㅣ·양순음 받침·휴지는 닫힘
- **눈**: 대사의 표정 지시(기본/설명/경고/놀람)에 따라 베이스 이미지를 **즉시 교체**.
  교체 시점은 대사 시작 0.15초 전 — 무음 공백 안이라 튀지 않는다

### ⚠️ 절대 부분 알파로 섞지 말 것

가장 중요한 규칙이다. 입이나 표정을 **중간값으로 블렌딩하면 두 이미지가 동시에 비쳐
이중 노출처럼 보인다**(닫힌 입과 열린 입이 겹쳐 보임). 실측에서 바로 드러났다.

- 입: 0~1 부분 블렌딩 ❌ → 임계값 이진 판정 ⭕
- 표정: 0.45초 디졸브 ❌ → 무음 구간에서 즉시 교체 ⭕

디졸브는 원리적으로 두 그림을 겹치는 연산이다. 2D 캐릭터에서는 어떤 길이로도
"자연스러운 전이"가 되지 않고 유령처럼 보인다. 2D 애니메이션이 표정을 **홀드 단위로
즉시 바꾸는** 이유가 이것이다.

영역 가장자리 페더는 유지해도 된다 — 그 구간은 두 이미지가 **이미 동일**하므로
(차이는 입 안쪽·눈 안쪽에만 있다) 겹쳐 보이지 않는다.

**검증**: 입 영역의 평균 밝기를 시계열로 뽑아 정규화했을 때, 값이 중간대(0.3~0.7)에
있는 프레임이 **0%** 여야 한다. 중간대가 있으면 블렌딩이 남아 있는 것이다.
- 3장의 표정 이미지로 **4가지 조합**이 나온다. 예: `경고`(매서운 눈) 베이스에
  `설명`의 입 영역을 덮으면 "매서운 눈 + 열린 입"

### ⚠️ 입 박스는 **다른 표정의 눈이 내려오는 곳**을 침범하면 안 된다

입 박스는 "입만" 덮어야 한다. 표정에 따라 **눈 크기가 달라지는 캐릭터**라면,
가장 큰 눈이 내려오는 y 좌표 아래에서 박스를 시작해야 한다. 안 그러면 놀란 표정으로
말할 때 **다른 표정의 작은 눈이 큰 눈 위에 덮여** 눈이 겹쳐 보인다(실측).

행별 차이 분포로 눈·입 y 범위를 먼저 잰다:

```bash
node /tmp/prof.mjs 기본.png 입벌림.png "입"    # → 입이 있는 y 대역
node /tmp/prof.mjs 기본.png 놀람.png   "큰 눈"  # → 큰 눈이 내려오는 y 하한
```

실측 예 (토리 1380×752): 큰 눈 y408~575, 입 y552~671 → **입 박스는 y585 부터**.
(눈과 입이 붙어 있는 캐릭터라 입 윗부분을 조금 포기해야 했다)

### ⚠️ 소스 컷아웃이 이미 잘려 있으면 디자인 요소로 가린다

외부에서 받은 클로즈업 컷아웃은 **머리 위·몸 아래가 원본에서 이미 잘려 있는** 경우가
많다. 알파 행별 픽셀 수로 확인한다 — 첫 행/마지막 행에 픽셀이 이미 많으면 잘린 것이다.

```bash
node /tmp/alpha.mjs cut.png      # y0=337px 처럼 첫 행부터 내용이 있으면 잘림
```

실측: 너굴은 y0 부터 337px(귀 끝이 평평하게 잘림), 아래도 y767 까지 꽉 참.

**가로형 컷아웃은 세로 프레임을 채울 수 없다.** 1407×768(가로 1.83:1)을 1080×1920
(세로 0.5625:1)에 넣으면, 폭을 맞췄을 때 높이는 프레임의 **39%** 밖에 안 된다.
남는 위아래를 그냥 배경으로 두면 잘린 단면이 그대로 보인다.

→ **상단 띠 + 책상**으로 덮는다. 원본 대화장면도 위는 책장, 아래는 책상으로
잘린 면을 가리는 구조다. 띠에는 숫자 카드를 앉히면 기능까지 겸한다.

```
상단 띠(0.09) → 캐릭터(0.39~0.43) → 책상(0.52)
```

⚠️ **캐릭터마다 상단 여백이 다르므로 세로 위치를 따로 계산한다.**
컷아웃 상단에 여백이 없는 캐릭터는 이미지 y0 을 띠 뒤로 숨기고, 여백이 있는
캐릭터는 그 여백만큼 내려 귀가 띠 아래로 나오게 한다. 한 값으로 통일하면
한쪽은 귀가 잘리고 다른 쪽은 단면이 드러난다(실측).

⚠️ **책상 상단은 캐릭터 하단(=이미지 하단)과 같거나 위여야 한다.** 조금이라도
아래면 그 틈으로 잘린 단면이 보인다.

⚠️ 숫자 카드의 `MarginV` 는 띠 안에 들어가는 값이어야 한다. 크면 띠 밖으로
내려와 **캐릭터 얼굴을 덮는다**(실측: 300 → 52 로 수정).

### ⚠️ 책상 높이는 원본 아트의 비율을 따른다 — 절단면을 덮으려고 키우면 안 된다

컷아웃의 잘린 몸통을 가리려고 책상을 키우면 **벽처럼 보여 원근이 무너진다**
(실측: 책상 52%, 상단이 프레임의 49% → 비현실적).

제공된 원본 대화장면을 재보면 **책상 상단 66%, 책상 높이 34%** 이고,
청자 뒷모습의 머리 꼭대기가 책상 상단 근처에 온다. 이 비율을 그대로 쓴다.

책상을 낮추면 캐릭터 하단 절단면과 책상 사이에 틈이 생긴다.
**몸통을 늘려 메우려 하지 말 것** — 그건 임시방편이고 원근이 어긋난다.

→ **책상이 내려간 만큼 캐릭터도 내린다.** 캐릭터 하단 = 책상 상단이 되도록 배치하면
연장이 아예 필요 없다. 캐릭터를 내리면 잘린 머리 위가 드러나므로 **상단 띠를 그만큼
키워** 덮는다. 세 값이 하나로 묶여 있다:

```
띠 하단 + 캐릭터 높이 = 캐릭터 하단 = 책상 상단
```

실측 배치: 띠 22% → 캐릭터 하단 62% → 책상 38%.
(캐릭터 높이는 컨텐츠 폭이 프레임에 들어가는 최대치로 고정되므로, 책상을 더 낮추려면
띠를 더 키우는 수밖에 없다)

`bodyExtendTo` 는 접합부 1px 틈을 막는 **안전 여유(20~30px)** 로만 쓴다.
어차피 책상에 가려지는 구간이다.

청자 뒷모습도 같은 함수로 **프레임 하단까지** 연장한다. 안 하면 아래가 뜬다.

⚠️ **책상 판은 화면 폭을 꽉 채워야 한다.** 높이 기준으로 스케일하면 폭이 모자라
좌우에 배경이 드러난다(실측: 1080 중 705px 만 덮음). 폭·높이를 직접 지정해 늘린다.

### 다른 그림끼리는 정렬해도 겹쳐진다

"클로즈업 컷아웃의 잘린 귀를 대화장면 이미지에서 가져와 붙인다"는 시도는 실패했다.
동공 간격으로 배율(0.832)과 중점을 맞춰 겹쳐 봐도 **얼굴 비율 자체가 달라**
안경·코·입이 이중으로 보인다. 별개로 생성된 그림은 정렬 대상이 아니다.

### ⚠️ 캐릭터 크기는 "컨텐츠 폭"으로 계산한다 — 이미지 폭이 아니라

가로형 컷아웃은 이미지 안에 좌우 여백이 있다. 높이만 보고 키우면 **캐릭터가
프레임 밖으로 잘린다**. 알파 bbox 로 컨텐츠 비율을 먼저 재고 역산한다.

```
컨텐츠폭 = (bbox폭 / 이미지폭) × (이미지폭 / 이미지높이) × 렌더높이
         = 컨텐츠비율 × 이미지종횡비 × H_px
```

실측: 너굴 계수 1.328, 토리 1.224 →
컨텐츠를 1000px(양옆 40px 여백)에 맞추려면 각각 높이 **0.392 / 0.426** 비율.

### 레이어 순서

```
배경 → 화자 → 책상 → 청자 뒷모습(가장 앞)
```

⚠️ **청자 뒷모습이 화자 얼굴을 가리면 안 된다.** 가로형 컷아웃은 폭이 넓어 옆에
두면 겹친다. **화자 얼굴 아래쪽**(책상 높이 근처)에 오도록 `backBottom` 을 키워
내린다. 실측: 화자 얼굴 하단 ≈ `bottom×OH − 0.3×H_px`, 뒷모습 상단이 그보다 아래.

⚠️ **청자 뒷모습은 책상보다 앞**이다. 카메라와 가장 가까운 레이어이므로 책상 뒤에
두면 오버더숄더가 성립하지 않는다(실측: 뒤에 두니 책상에 가려 거의 안 보였다).

### 검증

같은 표정 구간에서 0.5초 간격 두 프레임을 비교한다. **차이가 입 영역 한 곳에만**
있어야 한다. 다른 곳에 차이가 있으면 캐릭터가 움직이고 있는 것이다.

렌더 속도: 54초 영상 **8초**. 비용 0. 재현 100%.

## 9. 생성형 립싱크 3경로

결정론적 경로(§5)와 달리 **비용이 발생하고 결과가 매번 달라진다.**
훅 3초나 리액션 클로즈업에만 쓰는 것을 권한다.

### ⚠️ 가장 중요한 제약: 평면 2D 동물 캐릭터에는 대부분 실패한다

이 파이프라인의 캐릭터(평면 벡터 펭귄)로 실측한 결과다.

| 입력 | 모델 | 결과 |
|---|---|---|
| 펭귄 완성프레임 (768×1280) | `cjwbw/sadtalker` | ❌ `can not detect the landmark from source image` |
| 펭귄 **얼굴 클로즈업** (512×512) | `cjwbw/sadtalker` | ❌ 동일 실패 — 얼굴을 꽉 채워도 안 된다 |
| **토끼** 얼굴 클로즈업 (512×512) | `cjwbw/sadtalker` | ❌ 동일 실패 |
| 펭귄 얼굴 클로즈업 | `devxpy/cog-wav2lip` | ❌ `IndexError` — cog 가 업로드 파일을 **확장자 없는 임시 경로**로 내려받아 `args.face.split('.')[1]` 이 터진다 (얼굴 검출 이전, 모델 래퍼 버그) |
| 펭귄 애니메이션 영상 8초 | `bytedance/latentsync` | ❌ inference 프로세스 exit 1 |

**대조군이 성공했으므로 파이프라인·업로드·스키마 매핑·폴링은 모두 정상이다.**
실패 원인은 오직 캐릭터 스타일이다.

**경계는 "카툰이냐 실사냐"가 아니라 "사람 얼굴 기하구조가 있느냐"다.**
이 모델들은 사람 얼굴로 학습된 랜드마크 검출기를 전제한다. 2D 애니 캐릭터가
되는 경우가 있는 것은 그 얼굴이 **사람 비율**(눈·코·입 배치·간격이 사람과 유사)
이기 때문이다. 부리·단색 면·넓은 눈 간격으로 이루어진 동물 캐릭터는
펭귄이든 토끼든 검출 자체가 되지 않는다.

**대응**:
1. **결정론적 경로(§5)를 기본으로 쓴다.** 이 캐릭터 스타일에서는 선택이 아니라 필수다
2. 생성형이 꼭 필요하면 **카툰 지원을 명시한 서비스**(Flyworks 등)를 쓰거나,
   video-to-video 모델에 이미 애니메이션된 영상을 넣는다
3. 캐릭터 디자인 단계에서 결정된다 — 생성형 립싱크를 쓸 계획이면
   **사람 비율 얼굴**로 설계해야 한다. 나중에 바꿀 수 없다

Replicate 모델 가용성은 변동이 크다. 2026-08-20 기준 404: `zsxkib/joyvasa`,
`cjwbw/aniportrait`, `zsxkib/hallo`, `zsxkib/echomimic`, `zsxkib/musetalk`,
`chenxwh/v-express`, `zsxkib/live-portrait-animals`. 살아있음: `fofr/live-portrait`
(영상 구동, 오디오 아님), `cjwbw/sadtalker`, `devxpy/cog-wav2lip`,
`bytedance/latentsync`.

| 경로 | 공식 | 입력 | 상태 (2026-08-19 실행 검증) |
|---|---|---|---|
| **Flyworks** | 벤더 | 이미지/영상 | ✅ **영상 생성 성공** (40.0s / 832×1088 / 워터마크) |

전부 실패한 펭귄·토끼에서 정상적으로 입이 움직인다. 소요 약 7~10분/편.

로컬 저장에서 `{"error":"Video download failed: "}` 를 반환하며 파일을 쓰지 않는다

```bash
curl -sL -o output/flyworks.mp4 "<응답의 video_Url>"
```

### Flyworks 사용 시 반드시 감안할 4가지 (전부 실측)

1. **워터마크가 2개** — 좌상단 `AI生成`, 하단 중앙 `飞影数字人`.
   상단은 크롭으로 제거되지만 **하단은 캐릭터 발과 겹쳐 크롭이 불가능하다.**
   → **바닥 그림자 타원을 덮어씌운다.** 디자인 요소로도 자연스럽다 (`05-composite.mjs`).
   워터마크 위치는 클립마다 조금씩 다르므로 매번 확인할 것.
2. **피사체 중심으로 재프레이밍한다.** 입력 스틸에서 캐릭터를 오른쪽에 두어도
   출력은 가운데로 온다. **구도는 입력이 아니라 합성 단계에서 잡아야 한다**
   (`--scale` / `--posx` / `--posy`).
3. **얼굴을 자기 스타일로 재해석한다.** 눈이 감긴 곡선으로 바뀌고 부리가 입술처럼
   변형된다. 원본 벡터의 선명함이 사라지고 해상도도 줄어든다 (768×1280 → 736×1232).
4. **완성 프레임을 넣으면 배경까지 다시 칠한다.** 실측에서 한 클립은 배경이 보존됐는데
   다른 클립은 남색 벽이 갈색으로, 액자가 초록으로 바뀌었다. **클립마다 결과가 달라
   "같은 장소" 연속성이 깨진다.**
   → **대화 포맷에서는 완성 프레임 대신 그린스크린을 쓸 것.** 캐릭터만 뽑아
   내 배경 위에 올리면 배경이 100% 보존되고 워터마크 크롭도 자유롭다.
   비용은 호출 2회로 동일하다.

### 검증된 사용법: `MODE=dialogue_green`

대화 포맷은 **완성 프레임을 넣지 말고 그린스크린으로** 간다. 배경이 100% 보존되고
워터마크 크롭이 자유롭고 구도를 합성 단계에서 잡을 수 있다.

```bash
# 1) 캐릭터별 그린스크린 스틸 (캐릭터 크게 = 검출률↑, 위치는 무의미)
# 2) 화자별 풀길이 트랙으로 Flyworks 호출 2회
# 3) 배경 → 키잉된 화자(중경) → 청자 뒷모습(전경) 순으로 합성
MODE=dialogue_green node bin/05-composite.mjs \
  --green P=output/fw_green_P.mp4 --green R=output/fw_green_R.mp4 \
  --croptop 0.22 --cropright 0.19 --cropleft 0.06 \
  --name FLYWORKS_dialogue_OTS_9x16
```

**워터마크 위치는 클립마다 다르다.** 하단에 있을 때도 있고 **캐릭터 눈높이 옆에
붙을 때도 있다.** 그래서 `--croptop/--cropbottom/--cropleft/--cropright` 를 따로 준다.
캐릭터는 레이어 중앙에 있으므로 가장자리를 20%까지 잘라도 형태가 살아남는다.
좌우를 비대칭으로 자르면 캐릭터 중심이 이동하므로 `charCX` 로 보정한다(스크립트 내장).

**매번 프레임을 추출해 확인할 것.** 크롭 값은 클립마다 다시 잡아야 한다.

### 외부 제작 캐릭터 이미지를 쓸 때 (실측 정리)

**1. 길이 제한은 "압축 트랙"으로 넘긴다.**
무료 티어 45초 제한에 54초 대본을 넣어야 했다. 화자별로 무음을 빼고 자기 대사만
이어붙이면 크게 줄어든다(너굴 39.3s, 토리 7.0s). 각 줄의 `compactStart` 를
timeline.json 에 기록해 두면 합성 단계에서 원래 위치로 되돌릴 수 있다.
→ `01-build-audio.mjs` 의 3.5단계, `05-composite.mjs` 의 `MODE=compact`.

**2. 업로드 크기 한도가 문서보다 훨씬 낮다.**
1.8MB PNG → `File upload failed`. 같은 이미지를 112KB JPEG 로 줄이니 통과.
**입력 스틸은 JPEG 로, 200KB 이하로 만들 것.**

**3. 키 색을 하드코딩하지 말 것.**
재인코딩하면서 그린이 이동한다. 실측: 입력 `rgb(0,177,64)` → 출력 `rgb(0,165,58)`,
다른 렌더에서는 `rgb(0,160,55)`. **클립 모서리에서 실제 색을 읽어 쓴다**
(`05-composite.mjs` 의 `keyOf()`). 고정 색으로 키잉하면 캐릭터 주변에 반투명
초록 틴트가 레이어 크기만큼 남는다.

**4. 클로즈업 컷아웃은 프레임보다 크게 써야 한다.**
클로즈업 이미지는 어깨·귀가 원본 프레임에 잘려 있다. 이걸 중경 크기로 축소해
합성하면 그 절단면이 **사각형 테두리처럼** 보인다. 캐릭터 레이어 폭이 출력 폭을
넘도록 키워 절단면을 화면 밖으로 보낸다(실측: `spkh 1.08` → 레이어 폭 1193px > 1080px).

**5. 워터마크 위치가 렌더마다 무작위다.**
관찰된 위치: 좌상단 / 하단 중앙(발 위) / **얼굴 정중앙**. 얼굴에 걸리면 크롭으로
제거할 수 없다. → **렌더마다 프레임을 뽑아 확인하고, 얼굴에 걸리면 입력 스틸의
크기·크롭을 바꿔 재렌더한다**(입력이 바뀌면 위치도 바뀐다). 하단이면 바닥 그림자로
덮고, 가장자리면 레이어를 밀어 화면 밖으로 보낸다.

**6. 아바타 생성 실패.** 컷아웃 가장자리를 12px 잘랐더니 `Avatar creation failed`
(status 4). 6px 로 완화하니 통과. **과한 크롭은 얼굴 검출을 깨뜨린다.**

**7. 대사 사이 공백을 정지 프레임으로 채우지 말 것.**
압축 트랙은 대사만 이어붙인 것이라 타임라인의 공백(0.4~0.6s)에 해당하는 영상이 없다.
그 구간을 정지 프레임으로 채우면 **"영상 → 사진 → 영상"** 으로 눈에 띄게 튄다.
→ 압축 트랙의 무음 패딩(`COMPACT_PAD` 0.12s)을 `setpts` 로 **초저속 재생**해 채운다.
입이 닫힌 상태의 미세한 움직임이 이어져 컷이 튀지 않는다.

```
setpts=<공백길이/패딩길이>*PTS      # 예: 0.5s 공백을 0.12s 패딩으로 → 4.17*PTS
```

검증: 공백 구간에서 0.12s 간격 프레임을 뽑아 해시가 **모두 달라야** 한다.
같으면 아직 정지 프레임이다.

**8. 오버더숄더 원근 방향을 헷갈리지 말 것.**
카메라가 청자 뒤에 있으므로 **청자 뒷모습이 크고(가깝고), 화자가 작다(멀다).**
반대로 하면 원근이 뒤집혀 어색하다. 실측 비율: 화자 `spkh 0.52`, 전경 `fgh 0.58`,
전경은 `fgx 0.92 / fgb 1.18` 로 오른쪽 아래 모서리에서 잘리게 둔다.

**9-0. 워터마크는 고정 위치가 아니다 — 프레임 단위로 지워야 한다.** ⭐

가장 많이 헤맨 부분이다. Flyworks 워터마크는 **주기적으로 나타났다 사라지며
매번 다른 위치에** 뜬다. 실측(39초 클립):

```
t=1s  없음      t=2~3s   우측 중앙 (x≈720, y≈530)
t=4~15s 없음    t=16~17s 좌측 상단 (x≈360, y≈150)
t=18s~ 없음     → 984프레임 중 235프레임(24%)에만 존재
```

그래서 **한 프레임에서 좌표를 잡아 `delogo` 를 고정으로 거는 방식은 통하지 않는다.**
그 순간에만 맞고 나머지 구간에서는 워터마크가 그대로 떠다닌다.

→ `bin/07-strip-watermark.mjs` 가 raw 프레임을 스트리밍하며 **매 프레임** 검출·복원한다.

```bash
node bin/07-strip-watermark.mjs 입력.mp4 출력.mp4
# → "984프레임 중 235프레임 제거"
```

**복원은 시간축으로 한다.** 공간 보간(`delogo` 방식)은 털·질감 위에 **가로 얼룩**을
남긴다. 워터마크가 버스트로만 나타나므로 **직전 깨끗한 프레임의 같은 영역을 복사**하면
질감이 완전히 보존된다. 캐릭터 머리는 거의 정지 상태라 어긋나지 않는다.

```js
if (lastClean) lastClean.copy(buf, off, off, off + len);   // 시간축 복원 (권장)
else inpaint(buf, x0, y0, x1, y1);                          // 영상 첫머리 폴백
```

⚠️ raw 프레임을 파이프할 때 **백프레셔를 처리하지 않으면 `EINVAL` 로 죽는다.**
`write()` 가 false 를 반환하면 디코더를 `pause()` 하고 `drain` 에서 `resume()`.

⚠️ 검증은 보라 픽셀 수로 한다. 로고는 700px 규모이므로 **50~80px 수준은 배경**
(사무실 바인더 등)이지 워터마크가 아니다.

⚠️ **ffmpeg 두 개를 stdin/stdout 으로 직접 잇지 말 것.** 백프레셔를 `pause`/`resume`
으로 다뤄도, `await write()` 로 바꿔도 **뒷부분 프레임이 통째로 사라진다**
(실측: 984→910, 모든 클립에서 정확히 74프레임). 종료 시 인코더 stdin 에 버퍼링된
쓰기가 flush 되기 전에 끝난다. **디코드 → raw 파일 → 처리 → raw 파일 → 인코드**
로 단계를 분리해야 확실하다. 39초 클립 기준 임시 raw 2.7GB, 처리 후 삭제.

**반드시 프레임 수를 대조 검증할 것:**
```bash
ffprobe -select_streams v:0 -count_frames -show_entries stream=nb_read_frames -of csv=p=0 <파일>
```

**9-1. (참고) 위치가 고정인 워터마크라면 `delogo` 로도 된다.**

**9-5. 표정 전환은 무음 공백에서 크로스페이드한다.** ⭐

표정 클립을 하드컷으로 갈아끼우면 얼굴이 순간적으로 튄다. 대사 사이 무음 공백에서
0.35초 정도 겹쳐 넘기면 표정이 이어지듯 변한다(오디오가 없으므로 어긋나지 않는다).

**반드시 한 번의 ffmpeg 호출로 처리한다.** 임시 파일 2개를 만들어 `xfade` 로 잇는
방식은 짧은 구간에서 탐색이 어긋나 **0~1프레임짜리 입력**이 만들어지고 `xfade` 가
입력을 기다리며 **무한 대기**한다(실측: 3시간 경과 후에도 3/29 구간). `trim` 필터로
한 그래프 안에서 잘라 쓰면 이 문제가 없다. 단일 명령화 후 전체 렌더 **16초**.

⚠️ **`fps=24` 는 반드시 `setpts` 뒤에 둔다.** 앞에 두면 늘려도 프레임이 안 늘어난다
(0.04s=1프레임을 0.46s 로 늘려도 여전히 1프레임).

⚠️ 화자의 **첫 대사는 `compactStart=0`** 이라 앞쪽 패딩이 없다. 음수 탐색이 되지
않도록 `Math.max(0, ...)` 로 잠글 것.

**9-6. 표정별 색채를 맞춘다.** ⭐

표정 원본 이미지끼리 밝기가 다르고(실측: 경고가 기본/설명보다 **+17**), 생성형 툴이
클립마다 색을 또 다르게 이동시켜 렌더 후에는 **관계가 뒤집히기도** 한다.
그대로 이어붙이면 표정이 바뀔 때 캐릭터 색이 튄다.

각 클립의 캐릭터 영역 평균 RGB 를 재서 기준 클립에 맞추는 채널 게인을 건다
(`--colormatch <기준키>`, `colorchannelmixer`). 실측 게인: 경고 1.136/1.100/1.090,
놀람 1.080/1.060/1.034.

⚠️ **기준은 캐릭터마다 따로 잡는다.** 다른 캐릭터에 맞추면 색이 엉뚱해진다.
⚠️ 클립보다 뒤 시각을 샘플하면 **빈 버퍼가 돌아와 NaN** 이 된다. 길이 가드 필수.
Flyworks 워터마크는 두 종류다. `AI生成`(항상 좌상단, 크롭으로 제거)과
**보라 로고 + `飞影数字人` 텍스트**(위치가 렌더마다 바뀌고 얼굴 위에 얹히기도 한다).
후자는 크롭이 불가능하므로 위치를 찾아 `delogo` 로 지운다.

로고는 채도 높은 보라(파랑>빨강>초록)라 캐릭터·사무실 배경에 없는 색이다.
`bin/06-find-watermark.mjs` 가 이 색을 스캔해 좌표를 뽑는다:

```bash
node bin/06-find-watermark.mjs build/cu/clip.mp4     # → x:y:w:h
# 합성 시: --delogo <화자 또는 화자:표정>=x:y:w:h
```

⚠️ **전체 bbox 를 그대로 쓰면 안 된다.** 사무실 배경의 바인더처럼 보라 계열이 섞여
있으면 프레임 전체가 잡힌다(실측). 격자 밀도로 **최빈 셀 주변만** 취해야 한다.
로고는 작고 조밀한 덩어리다.

**9-2. 캐릭터가 잘리면 페더로 흐리지 말고 "책상 뒤"로 배치한다.**
클로즈업 컷아웃은 하단(몸통)이 원본 프레임에 잘려 있다. 이걸 페더로 흐리면
**가장자리가 뿌옇게 번져 부자연스럽다.** 대신 **책상 전경 레이어**를 깔아 절단면을
물리적으로 가린다. 캐릭터가 책상 뒤에 앉은 것으로 읽혀 잘림이 설명된다.

```
합성 순서: 배경 → 화자 → 책상(하단 절단면을 가림) → 청자 뒷모습(가장 앞)
```

책상 판은 제공된 대화장면 이미지에서 **캐릭터가 없는 구간**만 잘라 쓴다
(캐릭터가 걸치면 전경에 유령이 생긴다).

**9-3. 그린스크린 스틸을 만들 때 캐릭터를 잘라먹지 말 것.**
가로형 컷아웃(1407×768)을 세로 기준(`scale=-1:H`)으로 키우면 좌우가 캔버스 밖으로
나간다. **폭 기준(`scale=W:-1`)으로 맞추고 하단만 캔버스 바닥에 걸치게** 배치한다.
컷아웃의 알파 bbox 를 먼저 재서 좌우 여백이 얼마나 있는지 확인할 것.

**9-4. (참고) 축소한 컷아웃의 절단면을 페더로 녹이는 방법** — 책상 같은 전경을
쓸 수 없을 때의 차선책이다. 가장자리가 흐려 보이므로 권하지 않는다.
클로즈업 컷아웃을 중경 크기로 줄이면 원본 프레임에 잘린 어깨·귀가 직선으로 드러난다.
레이어 가장자리 알파를 램프로 떨어뜨린다(`--feather 100`). 이때 `geq` 앞뒤에
`format=rgba` 를 붙여야 알파가 보존된다. 알파 이진화를 함께 걸어
반투명 잔여물을 없앤다:

```
a='if(gt(alpha(X,Y),140),255,0)*min(1,min(X,W-1-X)/F)*min(1,min(Y,H-1-Y)/F)'
```

### 크로마키는 `colorkey`(RGB) 를 쓴다

`chromakey`(YUV) + `despill=type=green` 조합은 **캐릭터까지 반투명하게 만든다**
(흰 배가 통째로 빠졌다). 검증된 체인:

```
[1:v]crop=...,scale=...,format=rgba,colorkey=0x00B140:0.28:0.05[k]
```

## 10. 밟은 함정 (전부 실측 확인)

| 증상 | 원인 | 대응 |
|---|---|---|
| 루프에서 줄번호가 밀리고 파일이 빔 | **macOS `say`가 stdin을 읽는다** — 루프 입력을 잠식 | `say ... < /dev/null` (ffmpeg도 `-nostdin`) |
| 특정 음성이 1.5KB 무음 파일 생성 | macOS가 **미설치 음성도 목록에 표시** | 길이 < 0.15s면 에러로 중단. 시스템 설정에서 다운로드 |
| 피치를 낮췄는데 2배 빨라지고 높아짐 | `say -o`는 **22050Hz**, `asetrate=44100*p`가 기준 불일치 | 먼저 `aresample=44100` 통과 (§4) |
| rate를 바꿨는데 길이가 그대로 | `say -r`이 **이산 양자화** (128 == 150) | gap으로 조절 (§6) |
| `exec format error` | `find | head -1`이 linux 바이너리를 잡음 | `bin/<platform>/<arch>/ffprobe` 로 명시 |
| 립싱크가 엉뚱한 얼굴에 붙음 | 모델은 **프레임당 얼굴 1개**만 처리 | 캐릭터별 개별 렌더 후 합성 (§4) |
| Canva로 타이밍 제어 불가 | `edit-design`에 **페이지 duration 연산이 없다**. 애니메이션·오디오 연산도 없음 | Canva는 썸네일·숫자카드·정적 에셋 전용 |
| MCP 등록했는데 도구가 안 보임 | MCP는 **세션 시작 시 로드** | 재시작 또는 `claude -p --mcp-config` (§9) |
| 한글 파일명 매칭이 전부 실패 | macOS `readdir` 은 한글을 **NFD(자모 분리)** 로 준다. 소스의 NFC 문자열과 `includes` 하면 항상 false (실측: 캐릭터가 5명으로 잘못 분리) | 파일명은 만질 때마다 `normalize('NFC')` |
| 캐릭터 폭이 갑자기 200px 커짐 | 체커 제거 후 남은 **고립 잔재**가 알파 bbox 를 오염 (실측 x195→x0) | `tool-keepmain` 으로 주 덩어리만 남긴다 |
| ROI 가 화면 전체로 잡힘 | 전 화면에 흩어진 안티에일리어싱 차이가 **하나의 거대 덩어리**로 이어짐 | 차이 덩어리를 **밀도**로 거른다 (실제 부위 0.25~0.31 / 잡음 0.003) |
| 흰 캐릭터가 세로 줄무늬로 망가짐 | 흰 잔재 제거 임계를 낮춰 **흰 토끼 몸통**까지 잡힘 | 크기 상한 + 순백(225/14) 유지. 임계를 낮추지 말 것 |
| 책상/배경 판이 미리보기에선 사라짐 | `geq` 에 `a` 식을 안 주면 **알파가 0**. `overlay` 기본 `format=yuv420` 이 알파를 버려 화면엔 그려져 **버그가 숨는다** | `a='alpha(X,Y)'` 필수. `crop=1:1` 로 알파 `ff` 확인 (§8.6) |
| 입이 열릴 때 **귀가 같이 움직임** | 표정마다 따로 귀를 재구성 → 띠 검출이 한 장만 실패 | `16b-sync-ears` 로 기준 한 장에서 복사 (§8.6) |
| 귀 이음선에 **가로 줄** | `--skip` 이 k=0 에서도 아래 단면을 가져옴 | skip 대신 **원본을 미리 crop** (§8.6) |
| 귀 끝이 **각지거나 주름** | 프로파일 끝이 직선 / 흐림 탭 고정 / 띠 경계 | 끝은 `sqrt(1-f)`, 탭은 반경 비례, `--post` 로 내부 후처리 (§8.6) |
| 확대해선 멀쩡한데 영상에선 이상함 | 귀·이목구비는 **실제 영상 배율 1:1** 로 봐야 판단이 맞는다 | 배경 위에 실제 크기로 얹어 확인 (§8.6) |

## 11. 실행 순서 (현행) — 캐릭터 이미지 + 대본 docx → 영상

### 입력 계약

```
assets/
  <캐릭터이름>/          ← 폴더 이름 = **대본 docx 의 화자 이름**
    앞_기본.png          ← 필수. 무표정 앞모습
    앞_<표정>.png        ← 0개 이상 (설명 / 경고 / 놀람 / 입벌림 …)
    뒤.png               ← 필수. 뒤통수 (오버더숄더 전경)
  scene.png              ← 선택. 배경·책상 판을 떠올 완성 장면
  대본.docx              ← 5열 표: # | 화자 | 대사 | 컷 | 화면
```

- 접두어는 `앞_`/`뒤` 대신 `front_`/`back` 도 된다. 그 외 파일명은 자유.
- **표정 개수·이름은 자유다.** 어느 표정이 "입 열린 그림"인지, 어느 표정이 자기 눈
  프레임을 가져야 하는지는 **23-measure 가 픽셀로 판정한다.** 규칙을 외울 필요 없다.
- 평평한 폴더(캐릭터별 하위 폴더 없이)도 받지만 추측이 자주 틀린다. 20단계 출력을 검수할 것.

**필요한 입력은 `assets/` 하나뿐이다.** `input/` 의 설정 파일(`speakers.tsv` `timing.conf`
`readings.tsv` `script.tsv` `cast.json`)은 20·21·21b 가 만든다. 빈 `input/` 에서 시작해도 된다
— 실측으로 `closeup/` 과 `bin/` 만 남기고 전부 지운 상태에서 영상까지 나오는 것을 확인했다.

### A. 대본 · 캐스트

```bash
node bin/20-scan-assets.mjs assets              # → input/cast.json (초안)
#  ⚠️ speakers[].name 이 docx 의 화자 이름과 같은지 확인·수정
node bin/21-docx-to-script.mjs assets/대본.docx  # → input/script.tsv
```

⚠️ **21 은 `input/script.tsv` 를 덮어쓰며 gap 을 기본값(0.45s)으로 되돌린다.**
꾸러미에 들어 있는 `script.tsv` 는 길이를 맞추려고 gap 을 줄별로 손본 상태다
(총 54.02s). 21 을 다시 돌리면 균일 gap 이 되어 54.37s 가 나온다 — 둘 다 정상이고,
골든 기준값과 대조할 때는 **꾸러미의 script.tsv 를 그대로 쓴 경우**가 기준이다.
대본을 바꿀 때만 21 을 돌리고, 그 뒤 §6 대로 gap 을 조정한다.

### B. 오디오 · 입모양 · 자막

```bash

```

### C. 컷아웃 정리 → 실측 → 조합 생성

```bash
node bin/22-ingest.mjs        # 체커 제거 + 고립잔재 제거 + 흰잔재 메움 + 표정 정렬
node bin/23-measure.mjs       # bbox·입/눈 ROI·귀 절단·K·입열림그림·표정접힘 전부 자동 산출
node bin/24-build-chars.mjs   # 귀 복원 + 동기화 + 눈·입 조합 8장 + input/exprmap.json
```

`23-measure` 출력에서 **반드시 눈으로 확인할 것**:
- `입 열린 그림` 이 맞는가
- `독립 표정` 목록이 맞는가 (눈이 기본과 같은 표정은 접혀야 한다)
- `귀` 가 "절단됨" 으로 나왔다면 K 값 — **K 는 실제 영상 1:1 로 확인**해야 한다(§8.6)

원본 아트 결함으로 자동 판정이 못 미치면 `input/cast.json` 에 예외를 준다:

```jsonc
"N": { …, "overrides": { "backTrimTop": 10 } }   // K / trimTop / backK 도 가능
```

### 절차

```bash
# 보내는 쪽 — zip 은 반드시 UTF-8 플래그 + NFC 이름으로 만든다 (아래 ⚠️ 참조)
python3 - <<'EOF'
import zipfile, os, unicodedata
with zipfile.ZipFile('lipsync-pipeline.zip','w',zipfile.ZIP_DEFLATED,compresslevel=9) as z:
    for f in ['PROCESS.md','package.json','package-lock.json','.gitignore']:
        if os.path.exists(f): z.write(f, unicodedata.normalize('NFC', f))
    for d in ['bin','input','closeup','mcp']:
        for root,_,fs in os.walk(d):
            for fn in fs:
                if fn == '.DS_Store' or fn.startswith('._'): continue
                p = os.path.join(root, fn)
                z.write(p, unicodedata.normalize('NFC', p))
EOF
#   → 약 15MB

# 받는 쪽
tar -xzf lipsync-pipeline.tgz && cd lipsync-pipeline
node -v            # 18+ (검증 v24.18.0)
npm install        # ffmpeg/ffprobe 바이너리를 이 기계용으로 받는다
say -v '?' | grep ko_KR    # 한국어 음성이 실제로 설치돼 있는지 (§1, §10)
```

그 다음 §11 을 처음부터 돌려 **골든 기준값과 대조**한다. 값이 다르면 §10 을 먼저 본다.
가장 흔한 원인은 TTS 음성 미설치와 샘플레이트다.

⚠️⚠️ **`zip` CLI 로 그냥 묶지 말 것.** macOS 의 `zip` 은 UTF-8 플래그(bit 11)를 세우지 않고
파일명을 **NFD 원시 바이트**로 넣는다. 맥끼리는 열리지만 윈도우·리눅스에서는 한글이
깨져 `cast.json` 의 경로가 파일과 안 맞는다. 위 파이썬 방식은 플래그를 세우고 이름을
NFC 로 저장한다. 검증:

